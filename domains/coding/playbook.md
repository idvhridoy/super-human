# Coding Playbook

> Do/don't list maintained by `@domain-mentor` from session evidence.

## Do
- Build > watch: every session produces runnable code; tutorials are seasoning, not the meal
- Type every line yourself — never copy-paste code you can't explain line by line
- Read error messages fully before changing anything; say the hypothesis out loud first
- Rubber-duck: explain the bug in plain words before asking for help
- Commit early and often once at L7+; small commits with clear messages
- Keep a "today I shipped" log — visible progress sustains motivation
- Plan before coding: 3-line description of what the program does, then write it

## Don't
- Don't skip exercises by watching solutions first — struggle 15–20 min before hints
- Don't install packages or create accounts without human approval (esp. if learner is a minor)
- Don't share personal info in code, commits, usernames, or public repos — no real name/location/age
- Don't publish/deploy anything publicly without human gate — local-only until approved
- Don't touch other people's credentials/API keys; never commit secrets (hard rule from L9)
- Don't grind tutorials back-to-back — one concept, one small build, then move on
- Don't let AI assistants write code the learner couldn't produce unaided — use for explanations, not output

## Safety notes (if physical)
- Ergonomics: screen at eye level, breaks every 30–45 min (20-20-20 eye rule)
- Screen-time limits per `learner/profile.md` and daily routine — code sessions don't override them
- `@safety-guardian` may append vetoes
