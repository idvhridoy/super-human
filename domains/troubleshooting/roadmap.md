# Troubleshooting Roadmap

> Maintained by `@roadmap-planner`. Dates adjusted from evidence, not wishes. Assumes ~2 sessions/week + a fault-log habit — every real breakage at home gets written up.

## Next 30 days
- [ ] Baseline: does the learner write problem definitions, or jump straight to fixes?
- [ ] L0 passed — 5 scenarios restated as problem definitions (expected / observed / since / changed)
- [ ] Reproduction drills started — 3 faults with written repeatable steps
- [ ] Fault log opened — every real household breakage gets an entry

## 60 days
- [ ] L1–L2 done — isolation exercises with predict-before-test outcomes
- [ ] First bisection runs — ordered sequence + timeline fault each
- [ ] 5-whys practice on real cases — at least one cause pushed past "human error"
- [ ] Cross-check: software bugs pair with `coding/` sessions — method here, syntax there

## 90 days
- [ ] L3–L4 done — bisection in ≤ log2(n)+2 tests; 3 root-cause write-ups defended
- [ ] L5 milestone — 3 complete fault reports through the full fix-verify-document loop
- [ ] First supervised device fault attempted (power → connections → parts order)
- [ ] ~24 sessions logged; fault log holds ≥10 real entries

## This year
- Target: through L7 code debugging and into L8 process debugging
- Stretch: L9 intermittent-fault case managed; capstone dossier drafted — the learner is the person things get handed to when "it just stopped working"
